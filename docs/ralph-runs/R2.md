## What R2 actually did

### 1. Dual-manifest layout

```
plugin/
  .cursor-plugin/
    plugin.json            # Cursor manifest (already existed; bumped to 0.2.0)
  .claude-plugin/
    plugin.json            # NEW — Claude Code manifest, 0.2.0
.claude-plugin/
  marketplace.json         # NEW — at REPO ROOT so `source: "./plugin"` resolves
```

- `plugin/.claude-plugin/plugin.json` carries name, version, description, author, repository, license, keywords. It deliberately omits explicit component paths so Claude Code auto-discovers `commands/`, `agents/`, `skills/`, `hooks/`, and `mcp.json` under the plugin root.
- The marketplace JSON lives at the **repo root** (`.claude-plugin/marketplace.json`), not inside `plugin/`. The Claude Code marketplace contract resolves `source: "./plugin"` relative to the directory containing `.claude-plugin/`, so placing it at the repo root keeps the plugin tree intact.
- `plugin/.cursor-plugin/plugin.json` was bumped from `0.1.0-alpha.1` to `0.2.0` for parity.

### 2. Commands rewritten as prompt programs

All six commands under `plugin/commands/` were converted from prose into Claude Code prompt programs:

- `aeo:status` — read-only summary of every site's current loop state.
- `aeo:bootstrap` — initialise site config, seed `data/sites/<id>/`.
- `aeo:audit` — single-page audit via `audit_page`.
- `aeo:fix` — submits a job to the cli-worker daemon and polls for completion.
- `aeo:track` — captures a citation snapshot via `track_citations`.
- `aeo:compete` — runs `compare_competitors` against named competitor URLs.
- `aeo:loop` — pre-flight check, then delegates to the `aeo-loop` agent.

Each command file now carries Claude Code frontmatter:

```yaml
---
name: aeo:<verb>
description: <one-liner>
argument-hint: "<expected positional args>"
allowed-tools: Bash
---
```

The body of each command is a numbered set of bash blocks that all go through one helper script: `plugin/scripts/aeo-mcp.sh`.

### 3. Generic MCP shell helper

`plugin/scripts/aeo-mcp.sh` is a single bash JSON-RPC client that every command uses:

- Argument 1: tool name. Argument 2 (optional): JSON input. Defaults to `{}` when absent.
- Curls `http://${LLM_SEO_LAB_MCP_HOST:-127.0.0.1}:${LLM_SEO_LAB_MCP_PORT:-7301}/rpc`.
- Unwraps the `{ ok, value }` envelope: prints `value` to stdout (pretty-printed when `jq` is available), exits 0.
- On `{ ok: false, error }`: prints the error envelope to stderr, exits non-zero with a code derived from the error severity.
- On JSON-RPC level error: prints the error and exits non-zero.

This means every command is one bash one-liner per MCP call, and contract changes only have to be fixed in one place.

### 4. Lifecycle hooks (Claude Code)

`plugin/hooks/hooks.json` wires three executable bash scripts in `plugin/scripts/`:

- `SessionStart` → `aeo-session-start.sh` — checks `claude` is on PATH and pings the MCP server. Logs status to stderr. **Always exits 0.**
- `PreToolUse` (matcher: `Bash`) → `aeo-pretooluse-claude.sh` — confirms the `claude` binary identifies as `Claude Code` (subscription CLI), not an API shim. Logs a warning if not. **Always exits 0** (fail-open per pratyaksha convention — never blocks the user).
- `Stop` → `aeo-stop-compaction.sh` — emits a one-line nudge with the AEO state location and suggests `/compact` for long sessions. **Always exits 0.**

### 5. Agent updated to use the helper

`plugin/agents/aeo-loop.md` was updated:

- Frontmatter now declares `allowed-tools: Bash, Read, Grep, Glob`.
- A new "How to call MCP tools" section points the agent at `${CLAUDE_PLUGIN_ROOT}/scripts/aeo-mcp.sh` so the agent goes through the same envelope-unwrapping path as the commands.
- The "Inputs you can rely on" section was rewritten to reference `data/sites/<site_id>/config.json` and to enumerate all 16 MCP tools by name and arg shape.

Both success-envelope and error-envelope paths are exercised end-to-end. The helper unwraps `{ ok, value }` correctly, and the error envelope surfaces with the actionable next step intact.
