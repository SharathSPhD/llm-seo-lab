## What R3 produced — the data plane and the citation-pull tool surface

### Schema (Supabase)

Seven tables, all owned by a `user_id` that is RLS-bound to `auth.uid()`:

```
profiles            (1 row per user)
use_cases           (the unit of work)
use_case_events     (append-only stage history)
recommendations    \
applications        \   children of use_cases —
measurements         |  guarded by assert_user_owns_use_case()
analyses           /
```

The trigger `assert_user_owns_use_case` is the second layer of defence: even if RLS were misconfigured on a child table, the trigger refuses inserts where `new.user_id` does not own `new.use_case_id`. This is the contract the MCP service-role client is bound by — service-role bypasses RLS, but cannot bypass triggers.

### MCP tool surface (after R3)

| Tool name | Verb | Persists? | Validates |
|---|---|---|---|
| `read_use_case_state` | read | no | use case existence (NOT_FOUND) |
| `record_use_case_event` | write | inserts `use_case_events`; updates `use_cases.current_stage` (best-effort) | spec §3.2 transition table (rejects illegal transitions with `INVALID_INPUT`) |
| `pull_recommend` | write | inserts 5 `recommendations` rows (one per charter principle × substrate knob) | use case ownership; rate-limited |
| `pull_apply_artifact` | read | no — the dashboard owns the `applications` insert | recommendation belongs to the use case (NOT_FOUND otherwise) |
| `pull_analyze` | write | inserts one `analyses` row | ownership; rate-limited; falls back to `verdict: "stub"` if Claude unavailable, `"inconclusive"` if no measurements |
| `track_citations` | **deprecated** | no | always returns `INVALID_INPUT` with `deprecated_v0_3_0` marker |
| `read_citation_trend` | **deprecated** | no | always returns `INVALID_INPUT` with `deprecated_v0_3_0` marker |

Tool count went from 16 → 21 (5 new). Two of the original 16 were replaced by their `*Deprecated` counterparts at registration time, which is why the tool-count assertions in `tests/server.test.ts` and `tests/integration.http.test.ts` now check `21` instead of `16`.

### The deprecation envelope decision (spec §5.2)

Spec §5.2 sketched a flat `{ ok: false, error: "deprecated_v0_3_0", message: "…" }`. The existing `Result<T, AeoError>` envelope already shipped to every caller (`apps/web`, `cli-worker`, the Claude CLI worker tests) requires `error.code` to be one of the `ErrorCode` enum values. Introducing a new `DEPRECATED` code would be a wire-format break for v0.2.0 callers that switch on the enum.

Decision: keep the wire shape stable. The deprecation token `deprecated_v0_3_0` is embedded in the `error.message` string; downstream consumers regex-match it. `error.code` is `INVALID_INPUT` and `error.actionable_next_step` points at the dashboard. Tests in `v0.3.0.test.ts` assert exactly this shape.

### Pratyakṣa-deltas honoured by R3

R2's `docs/triz/v0.3.0-pratyaksha-deltas.md` mandated three Buddhi gates and a set of new Sākṣī invariants. R3 wires the data substrate that the gates need:

- **G1 (charter adherence)**: `pull_recommend` refuses to insert a recommendation whose `triz_principle` is not in `CHARTER_PRINCIPLES`. The schema enforces no constraint here — but the only path that writes recommendation rows is the v030 tool, which only emits charter principles. (Adapter-level enforcement lands in R4.)
- **G2 (voice protection)**: voice is in `recommendations.payload.voice_profile`, not at row top-level. R3 reserves the field; R4 fills it from the per-substrate adapter constant.
- **G3 (signal sufficiency)**: `pull_analyze` sets `verdict: "inconclusive"` when `current.length === 0`, and falls back to `"stub"` when Claude is unavailable. Both verdicts cite no charter principles in `triz_principles_cited` unless Claude returns parseable JSON.

The iteration-keyed sublation invariant (R2) is honoured at the row level: every `recommendations`/`measurements`/`analyses` row carries an `iteration int` that is checked against `use_cases.current_iteration` by `pull_analyze` to compute `current` vs `previous` cohorts.
