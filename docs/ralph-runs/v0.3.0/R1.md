## Decisions hardened in R1

The five documents jointly hardened the following decisions, beyond what the master plan stated:

1. **Three substrates only** in v0.3.0 (`web`, `substack`, `youtube`). Other CMSes are explicitly deferred to v0.4.0.
2. **Local-first dashboard** on `localhost:3030`. Cloud hosting is v0.4.0.
3. **Within-use-case A/B over time** is the measurement substrate; competitor-gap A/B is archived.
4. **Stage machine of 8 states** (DRAFT, RECOMMENDED, APPLIED, REPUBLISHED, MEASURING, MEASURED, ANALYZED, ABANDONED) with the transition table reproduced in [`spec.md`](../../v0.3.0/spec.md) §3.2 and enforced in three places (UI, server actions, MCP).
5. **Iteration counter** is the unit of A/B; it increments on `ANALYZED → RECOMMENDED`.
6. **MCP and dashboard split** of write responsibilities: MCP writes `recommendations` and `analyses`; dashboard server actions write `use_cases`, `use_case_events`, `applications`, `measurements`. This split keeps Claude-CLI-mediated writes on one side and user-input-mediated writes on the other, which simplifies audit and RLS.
7. **`AuthUser` interface preservation** so existing widgets compile when the auth shim is replaced in R6.
8. **`LLM_SEO_LAB_AUTH_ENABLED=0` escape hatch** for users who want the v0.2.0 archive experience without standing up a Supabase project.
9. **`LLM_SEO_LAB_GIT_MIRROR=1` opt-in** to mirror state events to `data/use-cases/<id>/state.jsonl` for offline review and audit.
10. **`stub` verdict** in `analyses.verdict` so fail-open Claude-CLI output is statistically distinguishable from real verdicts.
