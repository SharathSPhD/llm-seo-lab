### Architectural decisions made in R4

1. **Shared-types boundary.** `Stage`, `Substrate`, `CharterPrinciple`, all six row types, `ArtifactPayload`, `AdapterUseCase`, `RecommendationDraft`, and `SubstrateAdapter` live in `packages/shared/src/types/v030.ts`. MCP's `mcp/src/tools/v030.ts` *also* re-declares structurally-identical row types so existing v0.3.0 cross-process tests keep importing from there — this is intentional belt-and-braces while v0.3.0 is alpha.
2. **MCP imports adapters via the workspace package boundary.** `plugin/package.json` exposes an `exports` map (`./adapters`, `./adapters/web`, …) so MCP says `import { getAdapter } from "@llm-seo-lab/plugin/adapters"` rather than reaching into a sibling workspace's source tree. This keeps the dependency direction `mcp → plugin` explicit and grep-able.
3. **The MCP layer no longer owns substrate-specific knob/engine/rationale tables.** The 5-row `CHARTER_PRINCIPLES` table previously hard-coded in `mcp/src/tools/v030.ts` is gone; MCP iterates `CHARTER_PRINCIPLE_LIST` and asks the adapter for the draft. Adding a new substrate is now a 1-file change in `plugin/scripts/adapters/` plus a single registry line in `plugin/scripts/adapters/index.ts`.
4. **Artifacts are `_keyed_` to charter principles, not heuristically generated.** Each substrate's artifact builder is a `switch (principle)` with a per-principle template. The R5 plugin commands and R6 dashboard get to assume that "atomic-snippet-density on substrate=substack" always produces a recognisable Markdown block, etc.
5. **Adapters are pure.** They never call `fs`, `fetch`, or Supabase. The MCP layer owns I/O. This keeps adapter tests synchronous and stub-free (33 tests, no setup hooks).

### Out of scope for R4 (deferred)

- Wiring the adapters into actual page sources (real HTML for `web`, real Substack draft snapshot, real YouTube Studio metadata). The R4 artifacts are structurally correct *templates* with placeholder slots; R5 (`/pull:apply`) and R7 (seed use cases) inflate them with the actual page content via Claude.
- `paste_html` artifact kind. Reserved in `ArtifactKind` union but no adapter emits it yet — this is the v0.4.0 vehicle for hosted-but-unowned web pages.

## Hand-off to R5

R5 (`/pull:*` commands + `pull-orchestrator` agent + manifest bumps) can rely on:

- `import { getAdapter } from "@llm-seo-lab/plugin/adapters"` returning a substrate-keyed `SubstrateAdapter`.
- The MCP tools `pull_recommend` and `pull_apply_artifact` already producing adapter-shaped payloads, so the slash commands only need to render+stream them.
- `CHARTER_PRINCIPLE_LIST` exported from `@llm-seo-lab/shared` as the canonical iteration order.
- `voice_profile` always surfacing in both `RecommendationDraft.voice_profile` and `ArtifactPayload.ancillary.voice_profile`, so the `/pull:apply` command's user-facing summary can quote it without reaching into the adapter.
