## What R8.2 delivered

A new workspace `packages/state` (`@llm-seo-lab/state@0.4.0`) that encapsulates
all v0.4.0 persistence behind a single `StateDriver` interface, with two
implementations:

- `JsonlSqliteDriver` — local; `better-sqlite3` plus a JSONL mirror.
- `D1HttpDriver` — hosted; Cloudflare D1 binding (Pages Functions).

The drivers share SQL strings, row mappers, and ownership/transition
invariants, so MCP tools and the Next.js dashboard can be retargeted at
either backend without code changes downstream.

## Schema translation (v0.3.0 Postgres → v0.4.0 SQLite)

| Postgres                          | SQLite/D1                                                       |
| --------------------------------- | --------------------------------------------------------------- |
| `gen_random_uuid()`               | driver-side `crypto.randomUUID()` injection                     |
| `timestamptz default now()`       | `text default (strftime('%Y-%m-%dT%H:%M:%fZ', 'now'))`          |
| `jsonb`                           | `text` (drivers serialize/deserialize; row-mapper parses)       |
| `text[]`                          | `text` (JSON array)                                             |
| Postgres enum types               | `text` + `check (col in ('A','B',...))`                         |
| `boolean`                         | `integer check (col in (0,1))`                                  |
| RLS `policy ... using (auth_uid)` | enforced in driver layer; ownership check before every write    |
| Trigger functions                 | none — drivers raise `IllegalTransitionError` / `Ownership...`  |

The new `pending_actions` table (intent queue, R8.6) is introduced in the
same migration: `(id, use_case_id, requested_stage, requested_by,
requested_at, status, executed_at, result)` with status `pending → executed
| failed`.
